*toolchain.txt*       Unified development dependency installation

Requires Neovim 0.11+. Independent parser backend: Git, Tree-sitter CLI and a C
compiler on macOS/Linux. Mason needs mason.nvim v2; the legacy treesitter adapter
needs nvim-treesitter main. See README.md for complete examples.

COMMANDS                                                   *toolchain-commands*

:Toolchain                                                    *:Toolchain*
    Open the live installation task window.
:ToolchainPlan                                                *:ToolchainPlan*
    Inspect configured requirements. No registry refreshes or downloads.
:ToolchainInstall [provider:name ...]                          *:ToolchainInstall*
    Queue all configured requirements or selected IDs asynchronously.
:ToolchainRetry [provider:name ...]                            *:ToolchainRetry*
    Retry failed, unavailable, or cancelled tasks with their original declarations.
:ToolchainCancel provider:name                                *:ToolchainCancel*
    Cancel a queued task. Running tasks cannot be cancelled.
:ToolchainLog                                                 *:ToolchainLog*
    Open a read-only snapshot of the persistent JSON-lines log.
:ToolchainUninstall tool:<package>
    Remove an independent tool activation pointer and PATH entry, retaining its
    version files for already running processes.
:checkhealth toolchain
    Validate declarations and report backend availability without installing.

Window keys: i install all configured requirements; r retry selected; c cancel
queued; Enter toggle details; q/Esc close without interrupting installation.

SETUP                                                        *toolchain-setup*
>lua
    require('toolchain').setup({
      concurrency = 2,
      requirements = {
        { provider = 'parser', name = 'lua' },
        { provider = 'tool', name = 'stylua', executable = 'stylua' },
        { provider = 'system', name = 'git' },
        { provider = 'system', name = 'html_beautify', optional = true },
      },
    })
<
The independent tool backend appends installed version bin directories to PATH;
set tools.path = 'skip' to disable this. The optional Mason compatibility backend
requires Mason setup separately and does not change its settings. Requirements
may also be a read-only function returning a list. Each entry has provider/name, plus optional executable, resolve (returns
an executable path or nil), and a managed-tool post-install hook. Choose one:
post_install(package) for synchronous hooks, or
post_install_async(package, done, log) for asynchronous hooks. Call done() after
success, or done(error) after failure. log(output) adds child output to task logs.

Async hooks retain the queue slot until their callback runs, including for an
already-installed Mason package; independent intact versions skip their hooks. Repeated completion callbacks are ignored. They have
no implicit timeout: wait(timeout) returns control but does not stop the hook.
An existing helper that starts a process and returns must be adapted to call done;
merely leaving it in post_install still treats its return as completion.

Other options: max_log_lines = 200 (bounded output chunks per task), notify = true
(failure notifications), log_file = stdpath('state') .. '/toolchain-tools.log'
(false disables persistence). Setup and require never start installations.

System requirements accept optional = true (default false). An absent optional
executable is unavailable, not failed; health reports it as information. Resolver
errors still fail. Retry rechecks unavailable tools after external installation.
Optional flags do not suppress Mason/parser installation or hook failures.

API                                                          *toolchain-api*
>lua
    local tc = require('toolchain')
    tc.plan()                    -- local checks; optional requirement list
    tc.install()                 -- queue requirements; returns task IDs
    tc.install_ids({'tool:stylua'})
    tc.status()                  -- copied task states, messages, attempts, logs
    tc.retry()                   -- failed/unavailable/cancelled; optional ID list
    tc.cancel('tool:stylua')     -- returns success, reason
    local finished, tasks = tc.wait(300000)
    tc.open()
    tc.log_file()
<
wait() needs a finite timeout in milliseconds. Completion includes failed and
cancelled tasks: check for installed/skipped/unavailable to accept completion
without required dependency failures.

Task IDs are provider:name. Active identical declarations share one task.
Plan states: available, check (deferred backend check), missing (system),
unavailable (optional system), failed.
Task states: queued, running, installed, skipped, unavailable, failed, cancelled.

User ToolchainUpdated fires for transitions/output; event.data contains id,
state, attempt, optional, message. Call status() to refresh custom UI integrations.

BOUNDARIES                                                   *toolchain-boundaries*

Concurrency limits submitted tasks, not every process inside an upstream
installer. Only queued tasks can be cancelled. Existing system/Nix executables
satisfy managed-tool requirements without installation or post_install hooks. Executables
inside Mason's install root still receive Mason package checks and hooks.

Logs contain lifecycle events, independent tool/parser build output and Mason output;
legacy treesitter adapter details stay in :TSLog. Persistent logs are append-only.
Task history lasts one session.
setup() resets history and is rejected while tasks are queued or running.

Independent parser sources and queries use pinned commit SHAs. Installation
builds and validates a complete version, then atomically changes its current
pointer. Failed builds preserve the previous version. Repeated installation
checks file hashes and repairs damaged artifacts. Shared-query dependencies are
installed first. Sources are cached; git/build output is captured in task logs.

Setup activates immutable runtime paths once per language. Restart Neovim after
installation to activate new versions. Old versions and site/parser installations
are retained for existing sessions and migration. nvim-treesitter is not required
by this backend; its pinned query collection is still used as data.

Setup registers parser filetype aliases and compatible kind-eq?/any-kind-eq?
predicates without replacing existing providers or custom language mappings.
Override aliases with parsers.filetypes = { tex = 'my_latex' }; false skips defaults.

Configure parsers.install_dir, parsers.cache_dir, parsers.sources (per-language
overrides), parsers.filetypes and parsers.query_source. See README.md for the source schema. Inspect
require('toolchain.parsers').info(language) for receipts and integrity. General
package updates, uninstall and version pruning are not implemented.

INDEPENDENT TOOLS                                        *toolchain-tools-store*

The tool provider uses pinned recipes in data/tools.json; tools.sources can
replace or add definitions. Tools support release downloads, isolated npm
prefixes, Python virtual environments, Cargo Git tags and npm source builds.
No Mason modules are required. macOS/Linux x86-64 and ARM64 are supported when
upstream artifacts exist. Install at permanent version paths to preserve Python
shebangs, then atomically publish a current pointer. Failure retains the old
version. Explicit installation checks integrity and repairs modified artifacts.
New npm/Python installs record resolved dependency locks; repairs reuse intact
locks. Initial transitive dependency resolution is not globally locked.

require('toolchain.tools').executable(package, command) returns a managed wrapper.
.path(package, resource) returns a declared resource (omit resource for root).
.info(package) reports the current root, receipt and artifact integrity.
.remove(package) removes activation only, preserving files for live processes.
Tool hooks receive { name, path, version, resources } before publication; intact
versions skip hooks. Use ToolchainInstall after updating the pinned recipe.
Restart existing clients after installing a new tool version.
